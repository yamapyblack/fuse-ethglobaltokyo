# Fuse｜ハッカソン版 要件サマリ

**目標：** 1人・1日で、AIを活用してWebアプリ・画像素材・デモ動画まで制作する。  
**コンセプト：** 2体のNFTを消費して、AIが合成した1体を生み出す。Remintは今の子NFTを捨てる、後戻りできないガチャ。

## 1. 基本ルール

- **親NFT：** 自分が所有する2体を使用。burn機能の有無に依存せず、プールコントラクトへ永久ロックする。プールにはNFTの出庫・再承認・汎用外部実行・アップグレード機能を設けない。
- **子NFT：** 自作ERC-721として先にmintし、AI画像の生成後にメタデータを設定する。完成した子NFTも次の配合素材として使える。
- **料金：** 初回Fuse・Remintともに **0.001 ETH＋ガス代**。デモではテストETHのみ使用する。

## 2. ユーザーフロー

| 段階 | 処理 |
| --- | --- |
| ① 選択・承認 | 親NFTを2体選択し、それぞれをFuseコントラクトにapproveする。 |
| ② 初回Fuse | ユーザーが0.001 ETH付きのtxを送信。親2体のプールへのtransferと、新しい子NFTのmintを同一txで実行する。失敗時は全体を巻き戻す。 |
| ③ 画像生成・反映 | バックエンドがイベントを検知。親2体の画像をOpenAI APIへ送り、合成画像を1枚生成する。画像・メタデータJSONをS3またはR2へ保存し、子NFTのtokenURIを設定して画面に表示する。 |
| ④ 終了 | 結果に満足したら何もせず終了。すでにNFTは発行済みなので、追加のMint・確定操作は不要。 |
| ⑤ Remint | 警告を確認後、所有者が再び0.001 ETH付きのtxを送信。現在の子NFTをburnし、別のtokenIdの子NFTを同一txでmintする。親NFTは再投入しない。 |
| ⑥ 再生成 | 元の親2体の画像と新しい生成条件を使って再生成。新しい子NFTのメタデータを設定し、画面を新結果に置き換える。 |

**Remintの制約：** txが取り込まれると旧NFTは復元できない。画面に出す結果は常に1体のみ。新旧比較・過去候補の選択・元に戻す機能は作らない。画像のコピーや保存済みデータまで消せるという意味ではない。

## 3. 最小実装

| 構成 | 要件 |
| --- | --- |
| コントラクト | `fuse(...) payable`、`remint(tokenId) payable`、バックエンド専用のメタデータ確定処理。料金・所有権・親2体が別個体であることを検証する。子NFTのみRemint可能とする。 |
| 記録 | 親のコレクションアドレスとtokenId、requestId、Remint回数、前の子tokenId、生成状態を記録する。Remint後も元の親情報を引き継ぐ。 |
| バックエンド | イベント検知 → 画像生成 → 保存 → tokenURI設定。APIキーとメタデータ更新用秘密鍵はサーバー側のみで保持する。 |
| 保存先 | **AWS S3またはCloudflare R2のどちらか1つ**。画像とメタデータJSONをHTTPSで参照可能にする。親画像もスナップショット保存し、Remint時に同じ2枚を使用する。IPFSは使わない。 |
| Seed | 取り込まれたブロック情報とrequestIdから算出し、配合条件・プロンプトに反映する。画像生成はオフチェーン。完全再現や公平な乱数の保証は対象外。 |
| 失敗対応 | 生成中はRemint不可。生成失敗時は、同じrequestIdで追加課金・再mintなしに処理を再試行する。完成後のメタデータは再設定不可とする。 |

## 4. 画面・制作範囲

**画面は2つ：** 親2体を選んでapprove・Fuseする画面／生成状態・結果1体・Remintボタンを表示する画面。Remint前に「現在のNFTはburnされ、元に戻せません」と確認する。デザインは白背景・薄紫・かわいいカードで統一し、未実装メニューは置かない。

**対象：** テストネット1つ、自作NFTコレクション1つ、初期素材26体、画像生成モデル・画風は固定。外部NFTの一般対応、売買、対戦、能力値、レア度、SNS連携、独自通貨は対象外。

**成果物：** 動くWebアプリ、初期NFT画像26枚、60〜90秒の実画面デモ動画。動画は「選択 → 承認 → Fuse → 結果 → Remint確認 → 新結果」を収録し、生成待ちは短縮した旨を表示する。AI動画生成や凝った演出は行わない。
